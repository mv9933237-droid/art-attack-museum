|---|---|---|---|---|

| REQ-010 — Consultar ubicaciones | HU-02 FASE 4 | La respuesta incluye conteo de obras en cada ubicación. | `LocationController` (index, show, artworks), rutas API. | Feature: `LocationTest` — listado, detalle, obras de una ubicación. |

| REQ-013 — Registrar exposición | HU-02 FASE 5 | Exposición puede ser física o virtual. Fechas definen el período. | `ExhibitionController` (store), rutas API, modelo `Exhibition`, migración `create_exhibitions_table`. | Feature: `ExhibitionTest` — crear exposición física/virtual válida. |
| REQ-014 — Asignar obra a exposición | HU-02 FASE 5 | Una obra no puede participar en dos exposiciones físicas con períodos solapados. | `ExhibitionArtworkController` (store), `ExhibitionService` (assignArtwork), rutas API, modelo `ExhibitionArtwork`. | Feature: `ExhibitionTest` — asignar obra, rechazar solapamiento físico. |
| REQ-015 — Registrar reserva | HU-02 FASE 6 | Solo obras DISPONIBLES pueden reservarse. | REQ-016 — Cancelar reserva | HU-02 FASE 6 | Solo reservas ACTIVAS pueden cancelarse. Cancelación devuelve obra a DISPONIBLE. | `ReservationController` (cancel), `ReservationService` (cancel), rutas API. | Feature: `ReservationTest` — cancelar reserva, devolver estado. |
| REQ-017 — Registrar cliente | HU-02 FASE 6 | Todo cliente tiene documento de identidad único. | `CustomerController` (store), rutas API, modelo `Customer`, migración `create_customers_table`. | Feature: `CustomerTest` — crear cliente, documento único. |
| REQ-018 — Consultar clientes | HU-02 FASE 6 | Los clientes se listan por apellido. | `CustomerController` (index, show), rutas API. | Feature: `CustomerTest` — listado, detalle. |
| REQ-019 — Registrar venta | HU-02 FASE 7 | Una venta puede incluir múltiples obras. Moneda: BOB. | `SalesController` (store), `SaleService` (create), rutas API, modelo `Sale`, migración `create_sales_table`. | Feature: `SaleTest` — crear venta válida, múltiples obras, moneda BOB. |
| REQ-020 — Confirmar venta | HU-02 FASE 7 | Solo ventas PENDIENTES pueden confirmarse. Obras cambian a VENDIDA. | `SalesController` (confirm), `SaleService` (confirm), rutas API. | Feature: `SaleTest` — confirmar venta, cambio de estado de obras. |
| REQ-021 — Anular venta | HU-02 FASE 7 | Solo ventas CONFIRMADAS pueden anularse. Obras vuelven a DISPONIBLE. | `SalesController` (annul), `SaleService` (annul), rutas API. | Feature: `SaleTest` — anular venta, restaurar estado de obras. |
| REQ-022 — Registrar pago | HU-02 FASE 7 | Pago es físico (efectivo/transferencia). Moneda BOB. | `PaymentController` (store), rutas API, modelo `Payment`, migración `create_payments_table`. | Feature: `PaymentTest` — registrar pago, método válido, moneda BOB. |
| REQ-030 — Exclusividad de obra original | HU-02 FASE 7 | Una obra original solo puede tener una venta confirmada. | `SaleService` (create) — validación de exclusividad. | Feature: `SaleTest` — rechazar segunda venta de original. |

| REQ-032 — Anti-solapamiento físico | HU-02 FASE 5 | Una obra NO puede participar en dos exposiciones físicas con períodos solapados. | `ExhibitionService` (hasPhysicalOverlap), `ExhibitionArtworkController`. | Feature: `ExhibitionTest` — rechazar solapamiento, permitir consecutivas. |

| REQ-056 — Tipo de exposición | HU-02 FASE 5 | Solo dos tipos: physical, virtual. | `StoreExhibitionRequest` (in:physical,virtual). | Feature: `ExhibitionTest` — tipo inválido rechazado. |
